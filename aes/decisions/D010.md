# D010 — a widget test cannot wait for a room change, and does not need to

## The question D006 could not answer

D006 said the party left every tree, and that the harness cannot reach a door, so
the fix rested on review alone. Both halves were true at the time and the second
one was doing work it should not have been: it was used to explain the absence of
a test, when the absence had a different and simpler cause.

## What was measured, and what it forbids

Three requirements in a `testWidgets`, mutually exclusive. Each was measured, not
argued:

- `transitionTo` awaits the new room's tileset decode, which needs the real event
  loop, so it must start inside `runAsync`.
- `runAsync` denies a second call while the first is pending, so it cannot be the
  thing driving the change to completion.
- Mounting the room needs `pump`, and every render test freezes the engine so two
  frames differ only by what the test changed — so nothing turns until
  `resumeEngine`.
- `resumeEngine` restarts the game's own `GameLoop` timers, which the binding
  counts as pending async work, and `runAsync` is then refused. An empty `runAsync`
  at the top of the same test body passes.

Forcing it also fails, and both were measured: `game.update(0)` by hand inside
`runAsync` (400 turns, no completion — the lifecycle pass never runs) and `withLoop`
(deadlock, same cause).

## What this decides

Awaiting the whole transition is **not possible** in a widget test. Asserting the
invariant **is**, and that is the claim that matters.

The test starts the transition without awaiting it, samples the scene at every
step, and requires that both characters be in a tree the game draws throughout.
That is the invariant the original bug violated, and it is the one a player would
have felt. It does not require the destination room to finish loading, and it never
claimed to.

## What it does not license

`integration_test` is still the right instrument for "does the whole door work from
a player's seat", and it is still not built. This record says the widget harness can
hold the invariant, not that the browser has been driven through a door.

A test that cannot be awaited must not be written to pretend otherwise: the
earlier version of this ticket's test asserted the destination room and would have
failed for a reason that had nothing to do with the party.
