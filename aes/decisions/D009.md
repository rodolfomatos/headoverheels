# D009 — rebuild the scene exactly as the code built it, or do not measure it

## What was measured

One entity, `switch_1`, three conventions, three different answers in one run:

```
room_render_test   (cumulative removal)     3200px
room_placement_test (whole room present)     no box
```

and then, once both conventions were rebuilt correctly:

```
before     after
door_east    3200px   6400px
spring_1      800px   1600px
hushpuppy_1   800px   1000px
fish_1       2400px   3200px
switch_1        0px   3200px
```

Four of those were wrong before and nobody knew why.

## What was wrong with each convention

**Collect the removals, restore after the loop.** By the third entity the first two
were already gone, so each number described a room emptied around the thing being
measured.

**Restore each entity before the next.** Fixed the accumulation and broke the draw
order: `add` appends, `children` is a `ReadOnlyOrderedSet` with no insert-at-index,
so the 1024-wide conveyor had been re-appended *after* the switch. The test was
manufacturing the occlusion it existed to detect.

**Why the numbers were inflated.** An entity measured against a room missing its
neighbours counts their disappearance as its own contribution, so the larger its
neighbours the more it was credited with. `door_east` was credited with half of
what it draws.

## The decision

Every child out, render, every child back in its original order except the one under
test, render, every child back. And assert that the rebuild is faithful before
measuring anything in it — a restore that cannot reproduce the scene makes every
subsequent number a measurement of the restore.

The aggregate check is deleted rather than demoted. It was kept as "the cheap smoke
test it always was", which is a name for a check that cannot fail, and it is the
reason every placement defect in this project passed.

One enumerated exception: `conveyor_1` is `x=0 width=1024` in the map. A slack wide
enough for a room-wide belt also admits a misplaced entity, so the exception names
an id instead.

## What this rests on

Moving the tilemap 400 pixels makes the guard fail and names what moved. The old one
passed with any entity anywhere. `room_placement_test.dart` and
`room_render_test.dart` both rebuild; neither asserts a number taken from a scene
either test rearranged.
