# Knight Lore — second example game

Knight Lore (Ultimate Play The Game, 1984) rebuilt as a data and rules package on
top of the reusable `iso_core` runtime. Its purpose in this repository is to
prove the engine is not tailored to a single game: everything specific to
Knight Lore lives here, everything generic stays in `iso_core`.

## Fidelity

Canonical to the original:

- The five areas: Knightlore Castle, the Jungle, the Witches' Cauldron, the
  Abandoned Mine and the Wizard's Tower.
- The curse: the sabreman is werewolf-cursed, has 40 days and nights, and the
  cauldron demands six ingredients before the remedy is complete.
- Only the sabreman, and only by day, may enter Melkhior's laboratory.
- The moonlight split into four knights (Jinx, Joronie, Achinda, Celist) with one
  colour each.
- Six spells: Flip, Magic Armour, Open Door, Telekinesis, Shield, Invisibility,
  all decaying over time.
- A sixteen position inventory shared by the party.
- Filmation: fixed room views that flip when the four knights stand in the four
  exits of a room.
- Puzzle furniture: chests, statues, balls, witches, portcullises, diamonds,
  caskets, chalices, golden keys.

Ours, on purpose:

- Room ids, names and the topology between them. The original layout is not
  copied; this is a coherent 15 room world that exercises the same mechanics.
- Spell lifetimes and the split behaviour are tuned values declared as data, not
  frame-exact reproductions of the 1984 engine.
- All art, tilesets and audio are generated by this project.

No original game code, ROM data, level data or graphics are included. The
reference material used was the public Spectrum Games Database entry and the
World of Spectrum game information text.

## Layout

```text
lib/src/knight.dart     the sabreman and the four knights
lib/src/spells.dart     the six spells, as data, with decay
lib/src/inventory.dart  the sixteen slot inventory
lib/src/curse.dart      curse, day/night, split, ingredients, filmation rule
lib/src/game/           the playable session: terrain, movement, interaction
lib/src/world/          the world definition in the generic iso_core format
assets/world/           the generated world.json
test/                   rules tests, session tests and the world export
```

## The session

`RoomSession` is the playable core and it holds no rendering: it walks the party
one tile at a time, reads walls from a `RoomTerrain`, follows exits (locked exits
need their key, a werewolf cannot use a doorway, the split knights need Open Door
or Telekinesis), picks items up, answers the wizard and the cauldron, advances
the sundial and splits or rejoins the party. A test walks the whole 15 room world
to prove every room is reachable on foot, not just in the graph.

Two decisions worth knowing:

- Exits are stored per room edge, so the engine never has two doorways on the same
  edge. The "down to the crypt" and "down to the mine" flavour is carried by the
  room ids (`castle_crypt`, `mine_shaft`, `cauldron_cave`) because the engine is
  two dimensional.
- The party shares one inventory. The curse state owns it, so an item the sabreman
  picks up is the same item the cauldron can be given.

## World data

`KnightLoreWorld.build()` is the single source of truth and returns an
`iso_core` `WorldGraph`, the same type the editor edits. The identical file is
written to `assets/world/knightlore_world.json`; `test/export_world_test.dart`
regenerates it and fails if the committed file drifts from the builder, and
`validateWorld` must report no errors.

This is the point of the example: the editor's Graph tab, the runtime world
loader and the game rules all read one file in one format.

## Running it

```bash
make run-knightlore     # flutter run -d web-server, opens on :8081
make build-knightlore   # flutter build web --release
```

Arrows or WASD walk, space acts on what is underfoot or in front, F skips to
night or dawn. The HUD shows the room, the days left, the cauldron's demands,
the sundial and the sixteen slot inventory.

## Art

`scripts/generate_knightlore_assets.py` draws everything:

- `assets/world/tiles/<area>.png`: isometric 64x32 diamond tiles (floor, wall
  block, wall top) with a palette per area.
- `assets/sprites/knights/`: the sabreman and the four knights as four frame
  walk strips.
- `assets/sprites/props/`: chests, cauldrons, the wizard, balls, statues,
  witches, portcullises, scrolls and diamonds, tinted per area.
- `assets/sprites/manifest.yaml`: written by `KnightLoreManifest.write()` in the
  same format the Head over Heels assets use, so the editor reads both games.

Room maps live in `assets/world/rooms/<area>/<room>.tmx` and are generated by
`RoomMapBuilder` (a test regenerates them and fails if they drift).

## Audio

There are no audio assets in the original that can be reused, so every sound is
computed: `lib/src/audio/audio_synth.dart` is a small synthesiser (pulse,
triangle, noise, glides and envelopes) and `knight_lore_cues.dart` turns it into
22 cues and one seamless ambient loop per area. `tool/generate_audio.dart` writes
`assets/audio/*.wav` from that code, and `test/audio_test.dart` fails if a file
on disk no longer matches what the synthesiser renders.

    dart run tool/generate_audio.dart

## Balance

`test/balance_test.dart` measures the game instead of asserting taste, and prints
what it finds. With the shipped tuning:

| Measure | Value |
|---------|-------|
| Days in the game | 40 |
| Ingredients to the cauldron | 6, one at a time, the wizard names each |
| A day holds | 18 room changes (`daySeconds` 24, 6 trap ticks a second, 8 ticks a step) |
| Knowing the world, six round trips | 48 changes, about 2.7 days |
| Walking all 15 rooms | 20 changes, about 1.1 days |
| Spell lifetimes | 2.5 to 3.5 in-game days, decaying at dawn only |

The two invariants that keep the clock honest: a player who knows the world
finishes in well under half the forty days, and a player who searches every room
still has time to spare. The forty days are for the search, not the fetch, which
is why the six ingredients each have one home in five different areas.

## Look

- `lib/src/render/ambience.dart` is the light of each place: the mine is warm and
  dark, the tower cold and blue, the jungle green. The room view washes the
  finished room with it, and every figure casts a soft shadow on the floor.
- A room change fades over about a fifth of a second, with the wash easing back
  in behind the fade.
- The HUD carries the sundial of the original: forty ticks, a marker for the day
  and a lit half for the night.

## Not implemented yet

- A menu.
- Caged monsters and hidden treasures: the original's optional set pieces. The
  generic prop sprite already draws them, only the room triggers are missing.
- The visual polish pass (shadows, room transitions, a sundial) and the balance
  pass (days, spell decay, treasure placement) are tracked as T045 and T048.

## Implemented since the first draft

- Traps and hazards: ball chains, impaler spikes, bouncing and falling blocks
  and surfacing demons, all driven by `HazardField` in `lib/src/game/hazards.dart`.
  A hazard hits once per visit, costs a day and puts the party back on the spawn
  tile, and `test/hazards_test.dart` proves no room can be sealed by one.
- The status scroll, the six ingredients, the chests and the win state, and the
  title, pause, victory and defeat screens.
- A visual regression gate: `test/visual_preview_test.dart` renders rooms off
  screen, writes `build/preview/*.png`, and fails if a room is blank, cropped,
  or if two areas draw the same frame.
