# D001 — the page is faithful; the game is not

## The question

T075 was nearly closed on the strength of a board paragraph saying the room's
canvas is distorted by the page and that a screenshot therefore cannot say
*where* the game draws. That paragraph was written by an agent; this record
tests it.

## Verdict: NÃO-SUPORTADA

The premise is false. The page presents the canvas exactly, and the distortion
is inside the game's centring.

## The falsifier I ran, and its output

The falsifier is a command, not a judgement. It walks the document *and every
shadow root* for a canvas and reports its intrinsic size, its CSS size, its
origin and the device pixel ratio.

    $ NODE_PATH=…/node_modules node /tmp/opencode/canvas_shadow.js
    { "canvases": [ { "depth": 1, "attrW": 1280, "attrH": 800,
                      "cssW": 1280, "cssH": 800, "left": 0, "top": 0,
                      "parent": "FLT-CANVAS-CONTAINER" } ],
      "dpr": 1 }

One canvas. Intrinsic 1280x800, CSS 1280x800, at the origin, dpr 1. A window
asked for 1280x800. There is no scale, no offset and no backing-store mismatch
to explain x 1.535 in y 1.087.

## What this refutes, and what it does not

It refutes the board's claim that the page lies. It does **not** yet say where
the 660,470 comes from.

Two measurements bracket the fault. Instrumented in a release build, the game
reports `canvasSize=Size(1280, 800)`, `scale=2.4`, `offset=(25.6, 73.6)` — the
same values the off-screen test asserts. The page shows the room's hard-edged
background rectangle with its top-left at (660, 470), and the room at roughly
half the size the off-screen test measures.

Those two are consistent with exactly one arithmetic: the room is being centred
for a canvas of 2560x1600. (2560-1240)/2 = 660 and (1600-664)/2 = 468, against
an observed 660,470. So some code path computes the centre from a size twice the
window it was given, while the transform the view reports is the 1280x800 one.

## The cheapest command that would settle the rest

Read the centring in `RoomView.render()` and find which size it divides by. If
it reads a cached `_previewOffset` that some path can leave at a 2560x1600
value, that is the fault and the fix is to stop caching it. That is a read of
one method — no build, no browser, seconds.
